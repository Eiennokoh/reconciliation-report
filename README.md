# reconciliation-report

A Python tool that reconciles custodian bank holdings against internal records, detects quantity, price and one-sided breaks, and classifies their likely causes with rule-based logic.
Claude writes only the narrative explanation for each break. Every number is computed in code, and if an AI explanation contains any number that does not match the computed facts, the whole explanation is rejected and replaced with a code-generated template.
The tool produces an HTML report and an Excel workbook, runs in mock mode without an API key, and logs token usage and estimated cost.

---

## 解決したい業務課題

運用会社が運用するファンドの株式や債券は、実際には信託銀行（受託銀行）やカストディ銀行が保管しています。ミドル・バックオフィスでは日次・月次で、**カストディから届く残高**と**社内システムの記録**を突き合わせ、ずれがあれば原因を調べて直します（残高照合、リコンサイル）。

実務では次のような理由で差異が出ます。

- 約定済み取引の未計上や受渡日のずれ
- 株式分割などのコーポレートアクションが片方にしか反映されていない
- カストディと社内で使っている価格ソースが違う
- 片方にしか銘柄が存在しない（計上漏れ、償還・売却の未反映）

差異の検出自体は機械的にできますが、件数が増えると「何が起きていそうか」「次に何をすべきか」を一件ずつ書き起こす作業が負担になります。このツールは、**検出と原因の切り分けをコードで自動化し、説明文の作成だけを AI に任せる**ことで、担当者がすぐ確認作業に入れる状態の報告書を作ります。

> データはすべて架空です（架空ファンド、約 50 銘柄の国内株式・日本国債）。実在の銘柄・金融機関とは関係ありません。

## 処理の流れ

```
読込 ──▶ 照合 ──▶ 分類 ──▶ 説明 ──▶ 報告書
CSV×2    コード    ルール    AI＋数値検査   HTML / Excel
```

| 段階 | 内容 | 担当 | ファイル |
|---|---|---|---|
| 読込 | 必須列・証券コード重複・数値・基準日をチェック | コード | `recon/loader.py` |
| 照合 | 証券コードで突き合わせ、数量差・価格差（許容誤差超え）・片側のみを検出し、評価額を計算 | コード | `recon/reconcile.py` |
| 分類 | 数量比・評価額・価格ソースなどのルールで原因を推定し、優先度を付ける | コード | `recon/classify.py` |
| 説明 | 差異 1 件ごとに説明文と対応案を作成。文中の数字を検査し、不一致ならテンプレートに戻す | AI＋コード | `recon/explainer.py`, `recon/validator.py` |
| 報告書 | サマリー・差異一覧・詳細・AI 利用状況を出力 | コード | `recon/report_html.py`, `recon/report_excel.py` |

### 照合ルール

- 数量：完全一致で判定
- 価格：国内株式は ±0.5%、日本国債は ±0.05 円（額面 100 円あたり）を超えたら差異
- 評価額：株式は「数量 × 単価」、国債は「額面 × 単価 ÷ 100」

### 原因の分類ルール

| 推定原因 | 判定条件 |
|---|---|
| 当社記録漏れの疑い | カストディにだけ存在 |
| 償還・売却の未反映の疑い | 当社記録にだけ存在 |
| 株式分割（併合）の未反映 | 数量比が 2・3・4・5・10 倍で、評価額の差が 1% 以内 |
| 取引の未計上 | 上記以外の数量差異 |
| 価格ソースの違い | 価格差異があり、価格ソースが異なる |
| 価格差異（原因要調査） | 価格差異があり、価格ソースは同じ |

優先度は、片側のみ・評価額差異 1,000 万円以上を「高」、分割・100 万円以上を「中」、それ以外を「低」としています。

## AI とコードの役割分担

| | コード | AI（Claude） |
|---|---|---|
| 差異の検出 | ✓ | |
| 数字の計算（数量差・評価額・差異率） | ✓ | |
| 原因の分類・優先度 | ✓ | |
| 説明文・対応案の作成 | | ✓ |
| AI の説明文の数字チェック | ✓ | |

**この分担にした理由**

1. **数字は再現性と説明責任が必要**
   照合結果は監査やファンドの基準価額に関わります。同じ入力なら必ず同じ結果が出ること、計算根拠を示せることが前提なので、検出・計算・分類はすべてテストできるコードで行います。
2. **AI が得意なのは「状況を言葉にする」部分**
   「なぜずれていそうか」「次に何を確認するか」を読み手に合わせて書くのは、ルールだけでは文章が硬くなりがちです。ここは AI に任せる価値があります。
3. **AI の誤りを前提に設計する**
   AI はもっともらしい数字を書くことがあります。そこで、プログラムが計算した値を facts として渡し、**説明文と対応案に出てくる数字はすべて facts の数量・単価・評価額のどれかと一致しなければ不合格**にしています（`recon/validator.py`）。次のものも不合格です。
   - AI が自分で計算した値（例：facts にない「2,500株」）
   - 符号が facts と逆の数字（例：+5,720,000円 を -5,720,000円 と書く）
   - 概数の表現（「約」「およそ」「程度」）、漢数字や「万・億」を使った数字（「三千株」「572万円」）
   - 基準日や証券コードに含まれるだけの数字（基準日 2026-10-30 の「10」など）

   不合格の説明は報告書に載せず、コードが作るテンプレート説明に差し替えたうえで、差し戻した文章と問題の数字を報告書に残します。正しいのに弾いてしまう誤検知は起こりえますが、その場合もテンプレートに戻るだけなので、誤った数字が載るより安全です。

## 安全性とコストへの配慮

- **AI に送るのは差異の行だけ**：一致した銘柄（サンプルでは 49 銘柄中 43 銘柄）は送りません。送る内容も差異 1 件分の facts に限定しています。
- **銘柄を特定できる情報は送らない**：説明文の作成には不要なので、証券コード・銘柄名・基準日は facts から除いて送ります（`recon/facts.py` の `facts_for_ai`）。報告書には載せます。
- **API キーはコードに書かない**：`.env` または環境変数から読み込み、`.env` は `.gitignore` で除外しています。
- **モデルは環境変数で切り替え**：既定は低コストの `claude-haiku-5-5`。`ANTHROPIC_MODEL` で変更できます。
- **出力トークンを抑える設定**：説明文は短いので `effort` を `low` にしています。Haiku 5.5 は思考が既定でオンで、思考のトークンも上限に含まれるため、`max_tokens` は 1,500 と余裕を持たせ、上限で切れた場合はエラーとして扱います。タイムアウトは 30 秒、再試行は 1 回です（`recon/config.py`）。
- **トークン数と推定費用を記録**：呼び出しごとの入力・出力トークン数と推定費用を、HTML と Excel（「AI利用ログ」シート）に出力します。料金は `recon/config.py` の料金表（USD / 100 万トークン）を使い、`PRICE_INPUT_PER_MTOK` / `PRICE_OUTPUT_PER_MTOK` で上書きできます。円換算は `USD_JPY`（既定 150）。
- **AI が使えなくても止まらない**：API エラー、JSON の崩れ、出力の途中切れがあればテンプレート説明に切り替え、照合結果と報告書は必ず出力します。

## 実行方法

Python 3.10 以上が必要です。

```bash
git clone https://github.com/<your-account>/reconciliation-report.git
cd reconciliation-report
python -m venv .venv
.venv\Scripts\activate             # macOS / Linux は source .venv/bin/activate
pip install -r requirements.txt

python main.py                     # API キーがなければ自動でモックモード
```

`output/` に HTML と Excel が出力されます。出力例は [`docs/sample/`](docs/sample/) にあります。

### デモ（1 コマンド）

```bash
python main.py --demo-hallucination --open
```

照合結果の一覧が端末に出たあと、HTML 報告書がブラウザで開きます。差異 6 件のうち 1 件（EQ0007）では、モックの説明文にわざと根拠のない数字（「前月末にも3,000株…」）を混ぜてあり、数値検査で差し戻されてテンプレート説明に差し替わる様子を確認できます。

### Claude API を使う場合

```bash
cp .env.example .env               # ANTHROPIC_API_KEY を記入
python main.py
```

### オプション

| オプション | 内容 |
|---|---|
| `--mock` | API キーがあっても API を呼ばずに実行 |
| `--demo-hallucination` | モック説明に根拠のない数字を混ぜ、数値検査で差し戻される様子を再現 |
| `--open` | 終了後に HTML 報告書をブラウザで開く |
| `--custodian` / `--internal` | 入力 CSV のパス（既定は `data/` のサンプル） |
| `--out` | 出力先フォルダ（既定は `output/`） |

### 入力 CSV の形式

```
as_of_date,security_code,security_name,asset_class,quantity,price,price_source
2026-10-30,EQ0001,架空精機,JP_EQUITY,28900,4100,東証終値
```

`asset_class` は `JP_EQUITY`（国内株式）または `JGB`（日本国債）。国債の `quantity` は額面金額です。サンプルデータは `python scripts/generate_sample_data.py` で再生成できます。

## テスト

```bash
pytest
```

API は呼ばずに実行できます。主に次を確認しています。

- サンプルデータに埋め込んだ 6 件の差異がすべて検出され、差異区分と推定原因が正しいこと
- 許容誤差内のノイズ（1 円・0.01 円のずれ）を差異にしないこと（誤検出ゼロ）
- 評価額・数量差などの計算結果、許容誤差の境界値
- facts にない数字、符号が逆の数字、概数、漢数字、基準日・証券コード由来の数字を含む説明文が差し戻されること（「一致」「十分」など数字を含まない普通の語は弾かないこと）
- API 応答を模したテスト用クライアントで、正しい応答の採用、誤った数字・壊れた JSON・途中で切れた出力の差し戻し、トークン数と費用の計算、証券コード・銘柄名を送っていないこと
- モックモードでパイプライン全体が動き、HTML と Excel が出力されること

## 限界と今後の改善

- **原因推定は単純なルール**：取引データ（約定・受渡日）やコーポレートアクション情報と突き合わせていないため、「未計上」と「受渡日のずれ」を区別できません。取引明細を読み込めば、原因をもっと絞り込めます。
- **数値検査は「出てくる数字が正しいか」だけ**：数字の使い方（例えば数量と評価額の取り違え）、「多い・少ない」といった言葉で書いた増減の向き、文章の論理までは検査していません。facts のキーと数字の対応づけまで見る検査は今後の課題です。
- **資産区分は国内株式と国債のみ**：外国株式（為替）、社債（経過利息）、投資信託などは未対応です。
- **数量・金額は外部に送っている**：証券コードと銘柄名は送りませんが、数量・単価・評価額は送ります。実データでは、社内承認済みの環境（Amazon Bedrock、Google Cloud の Vertex AI など）経由で呼ぶといった対応が必要です。
- **対応状況の管理**：現在は「未対応」で固定です。担当者の割り当てや前月からの持ち越しを追えるよう、結果をデータベースに保存する形にしたいと考えています。
- **呼び出し回数**：差異 1 件につき 1 回呼んでいます。件数が多い場合はまとめて送る、Batch API を使うなどで費用を下げられます。

├── tests/
